# Требования к внешним интеграциям

## 3.1 Требования к безопасности

| Требование                                                                                      | Обоснование                                                                                   |
|--------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------|
| Шифрование всего трафика между системой PropDevelopment и партнёрской платформой (TLS 1.3)      | Передаётся чувствительная информация — биометрия, номера автомобилей, доступы.               |
| Персональные данные в системе PropDevelopment шифруются при хранении                            | Обеспечение соответствия требованиям по защите ПДн (в т.ч. по 152-ФЗ, GDPR).                 |
| Биометрические данные обрабатываются и хранятся исключительно на стороне партнёра               | Минимизация рисков утечек и упрощение соблюдения требований к защите биометрии.              |
| Использование отдельных API-ключей или клиентских сертификатов для каждой точки интеграции      | Обеспечение разграничения доступа, возможность ротации и отзыва ключей.                      |
| Ограничение доступа по IP к API платформы партнёра                                               | Минимизация поверхности атаки, предотвращение несанкционированного доступа.                   |
| Включение двухфакторной аутентификации (2FA) для сотрудников PropDevelopment                     | Дополнительная защита административных и чувствительных операций.                            |
| Мониторинг и логирование всех запросов к API партнёра                                            | Возможность аудита и расследования инцидентов.                                               |
| Ведение отдельного аудита по действиям пользователей и систем                                    | Повышение прозрачности и отслеживаемости операций с ПДн и внешними системами.               |
| Регулярное тестирование уязвимостей на границах взаимодействия                                  | Своевременное выявление и устранение проблем безопасности.                                   |

---

## 3.2 Протоколы аутентификации и авторизации

| Протокол / механизм                        | Назначение                                                                                     |
|-------------------------------------------|------------------------------------------------------------------------------------------------|
| OAuth 2.0 + Client Credentials Flow        | Аутентификация между backend PropDevelopment и партнёрской платформой (машина-машина).         |
| JWT (JSON Web Token)                       | Представление прав доступа пользователя при проксировании вызовов от мобильного приложения.   |
| mTLS (mutual TLS)                          | Усиленная проверка подлинности для сервисов на уровне API Gateway.                            |
| TOTP (например, Google Authenticator)      | Реализация 2FA для административного доступа.                                                  |

## 3.3 Организация взаимодействия систем

| Компонент                                | Описание взаимодействия                                                                                         |
|------------------------------------------|------------------------------------------------------------------------------------------------------------------|
| Мобильное приложение                     | Отправляет команды (открыть дверь, открыть шлагбаум) и получает статус через backend PropDevelopment.          |
| Backend PropDevelopment                  | Выступает как прокси: авторизует пользователя, формирует вызов, перенаправляет на API партнёра.                |
| IoT-платформа партнёра                   | Получает запросы на управление устройствами (домофон, шлагбаум) и возвращает статус выполнения.                |
| API Gateway (на стороне PropDevelopment) | Выполняет маршрутизацию, проверку прав и защиту от несанкционированных запросов к платформе партнёра.         |
| Message Broker/Webhooks                  | Используется для получения событий от платформы партнёра (например, событие распознавания или отказа в доступе).|
